The safe path.

This is the install flow we want humans and agents to follow.

Golden rule

Do not paste Telegram tokens or LLM keys into the website. Give secrets only to local Spark setup.

Human steps.

macOS, Linux, WSL

Download, dry-run, install

curl -fsSL https://agent.sparkswarm.ai/install.sh -o spark-install.sh
bash spark-install.sh --dry-run
bash spark-install.sh
Windows

Download, dry-run, install

iwr https://agent.sparkswarm.ai/install.ps1 -OutFile spark-install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\spark-install.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\spark-install.ps1
Existing install

Upgrade after a dry-run

bash spark-install.sh --dry-run --upgrade-existing
bash spark-install.sh --upgrade-existing

Use this when Spark is already installed and your local CLI is missing newer commands from the docs.

What Spark may touch.

Network

  • agent.sparkswarm.ai
  • github.com/vibeforge1111/spark-cli
  • github.com/astral-sh/uv
  • nodejs.org

Local files

  • ~/.spark on macOS, Linux, and WSL.
  • %USERPROFILE%\.spark on Windows.
  • Autostart files when autostart is enabled.
  • Install logs under the Spark folder.

Needs testing

We should keep running production installer smoke tests whenever this list changes. New network destinations should be treated as a security review item.

Agent install schema.

Use this shape when an agent explains the install plan to a user.

spark-install-plan.v1for agents
{
  "downloaded": ["install.sh or install.ps1"],
  "verified": ["sha256", "attestation if available", "signature if available"],
  "dryRunShown": true,
  "writes": ["~/.spark or %USERPROFILE%\\.spark", "autostart files if enabled"],
  "secretsStayLocal": true,
  "needsUserApprovalBeforeInstall": true
}
