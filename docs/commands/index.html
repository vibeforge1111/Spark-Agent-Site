Commands

Know where to type each Spark command.

Some commands go in Terminal, CMD, or PowerShell. Some go inside your Telegram bot. Some things are better clicked in Mission Control. This page keeps those surfaces separate.

Agent Markdown Providers Fix

The three places Spark commands live.

If you know the surface, the command becomes much less scary.

01

Computer terminal

Use CMD, PowerShell, macOS Terminal, Linux shell, WSL, Codex, Claude Code, or another local coding assistant.

spark status
02

Telegram bot

Use slash commands inside the Spark bot you created with BotFather.

/diagnose
03

Mission Control

Use the browser UI when you want to see builds, Kanban, Canvas, and mission progress.

http://127.0.0.1:5173/kanban

First-day path.

Use this order when Spark is freshly installed or when you are helping someone else get unstuck.

Terminal

Set up Spark once

spark setup spark guide Expected: setup finishes, then the guide explains Telegram, LLMs, access levels, and first checks.
Terminal

Choose and test the model path

spark recommend llms spark providers status spark providers test --role chat Expected: chat, agent memory, and mission roles show the provider you chose.
Terminal

Turn Spark on quietly

spark live start spark live status spark autostart install --now Expected: Spark Live runs in the background without extra black terminal windows.
Telegram

Confirm the bot is alive

/diagnose

Telegram, LLM, memory, and Mission Control are checked.

/remember I like concise warm replies

Saved through Spark memory.

Telegram + Mission Control

Start a tiny build

/run say exactly OK

Spark creates a mission, posts progress in Telegram, and shows the work in Kanban or Canvas.

Command reference by surface.

Use the label on each row to know where to type it.

Terminal Setup and guidance spark setup spark guide spark recommend llms

Use when installing, changing your model provider, or relearning the first-run path.

Terminal Run Spark spark live start spark live status spark live stop spark autostart install --now

Use Spark Live for normal daily running. Use old module start commands only when a support guide asks for them.

Terminal LLM providers spark providers list spark providers status spark providers test --role chat spark setup --llm-provider codex

Use these when chat, memory, or missions are using the wrong model or no model.

Terminal Proof and repair spark status spark verify --onboarding spark verify --deep spark fix telegram spark fix spawner

Use these when something is quiet, unreachable, or confusing.

Terminal Telegram and secrets spark telegram connect spark secrets list spark secrets get telegram.bot_token

Use these when you need to connect a fresh BotFather token or confirm which secrets exist. Secret values stay masked unless you explicitly ask to reveal them.

Terminal Update safely spark update spark update --skip-dirty spark verify --onboarding

Use this when docs mention a command your local Spark does not know yet. Run verification after updating.

Terminal Logs, security, and support spark logs spark-telegram-bot --lines 80 spark logs spawner-ui --lines 80 spark security audit spark doctor llm "Telegram bot is quiet" spark support bundle

Doctor and support flows should redact secrets. Include logs only when you choose to.

Telegram Daily chat commands /start /myid /diagnose /remember <note> /recall <topic>

Use inside your Spark Telegram bot.

Telegram Build and mission commands /run <goal> /board /mission status <id> /access 3

Use these when you want Spark to build, check work, or change access level.

Browser Mission Control http://127.0.0.1:5173/kanban http://127.0.0.1:5173/canvas

Use the browser when you want to see what Spark is building instead of reading only chat updates.
