Provider families.

Subscription

OpenAI Codex

Best if the user already uses Codex or ChatGPT. Sign in with the Codex CLI, then choose Codex in Spark setup.

Subscription

Anthropic Claude

Best if the user already uses Claude Code. Use the Claude CLI sign-in path, including claude -p style prompts where available.

API Key

Z.AI GLM, Kimi, MiniMax, OpenRouter, OpenAI-compatible

Good when the user has an API key. Spark stores secrets locally and masks input in setup.

Local

Ollama and LM Studio

Good for local-first users. Spark should use only the selected local endpoint, not a surprise fallback.

Router

Hugging Face Router

Use when the user wants a hosted model router with an HF token and OpenAI-compatible chat endpoint.

Advanced

Separate mission provider

Keep chat/memory on one provider and missions on another only when the user asks for it.

What each role means.

Agent

Normal chat, runtime decisions, and memory. This is the user-facing Spark personality and reasoning path.

Mission

Spawner work: building, coding, research tasks, and longer tracked missions.

Default recommendation

For non-technical users, choose one provider and use it everywhere. If missions need a stronger or different model later, rerun spark setup and choose the advanced role split.
