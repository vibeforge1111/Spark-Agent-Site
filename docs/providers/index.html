Start with the easiest choice.

If you already pay for or use one of these tools, use that first. Spark can always be reconfigured later.

Already use OpenAI?

Choose OpenAI Codex

Use the Codex CLI sign-in path so Spark can use your existing Codex or ChatGPT setup without asking most users for an OpenAI API key.

spark setup --llm-provider codex
Already use Claude Code?

Choose Anthropic Claude

Spark can use the Claude CLI route when Claude Code is installed and signed in. This is the friendliest Claude path for many subscription users.

spark setup --llm-provider anthropic
Have an API key or local model?

Choose your provider

Use Z.AI GLM, Kimi, MiniMax, OpenRouter, Hugging Face, Ollama, LM Studio, or another OpenAI-compatible endpoint you already trust.

spark recommend llms

spark recommend llms

spark verify --onboarding

Agent and Mission, in plain English.

Agent

Conversation, memory, and Spark's day-to-day thinking.

This is what answers Telegram messages, remembers preferences, recalls context, and decides how Spark should respond.

Mission

Build work that goes through Mission Control.

This is what runs longer Spawner work: building apps, researching, debugging, and tracking progress on the Kanban or Canvas.

Default recommendation

Choose one provider first and use it for both Agent and Mission. If builds need a different model later, rerun spark setup and choose the role split.

Provider families.

Subscription

OpenAI Codex

Best if you already use Codex or ChatGPT. Connect with the Codex CLI sign-in path, then test chat.

spark providers test --role chat
Subscription

Anthropic Claude

Best if you already use Claude Code. Spark can use the Claude CLI route, including claude -p style prompts where your local Claude CLI supports them.

spark providers test --role chat
API Key

Z.AI GLM, Kimi, MiniMax, OpenRouter, OpenAI-compatible

Good when you have a provider key. Spark stores secrets locally and masks input during setup so keys are not printed in the terminal.

spark secrets list
Local

Ollama and LM Studio

Good for local-first users. The local app must be running, and Spark should use only the selected endpoint instead of falling back to a surprise local server.

spark providers status
Router

Hugging Face Router

Use this when you want a hosted model router with an HF token and an OpenAI-compatible chat endpoint.

spark providers test --role chat

What good looks like.

Provider status: Agent and Mission roles show the provider you chose.

No surprise fallback: Spark should not call Ollama, LM Studio, or another local endpoint unless you selected it.

Telegram chat: A normal message gets a real answer from the selected Agent provider.

Build test: /run say exactly OK starts a mission and returns a result through Mission Control.

spark providers status
spark providers test --role chat
spark verify --onboarding
