Setup

Telegram and your LLM provider are the two keys.

Telegram is how you talk to Spark. The LLM provider is the model Spark uses to think and reply.

Create a Telegram bot Open Telegram, message @BotFather, and create a new bot. Keep the token private.
Find your Telegram ID After Spark starts, send /myid. Use that number as the admin ID.
Choose an LLM provider Use Codex, OpenAI, Anthropic, Z.AI, MiniMax, Ollama, or another supported provider.
Run the checks Use spark providers status and spark verify --onboarding.
Daily Use

The commands people actually need.

In Telegram

  • /start opens Spark.
  • /diagnose checks what is working.
  • /remember <note> saves a memory.
  • /recall <topic> searches memory.
  • /run <goal> starts a mission.
  • /board shows mission status.

In Terminal

  • spark guide opens the walkthrough.
  • spark status checks Spark.
  • spark providers status checks models.
  • spark verify --onboarding checks setup.
  • spark autostart status checks startup.
  • spark doctor runs deeper checks.
Fixes

When Spark is quiet, check these first.

Most quiet-bot problems come from one of three places: Telegram token, admin ID, or LLM provider setup.

Telegram gets commands, but replies are weird

Run spark providers status.

If the model role is missing, Spark may only show memory labels or empty status text.

Telegram gets nothing

Run spark fix telegram.

Then run spark logs spark-telegram-bot and look for token or polling errors.

Memory does not come back

Run spark verify --deep.

This checks memory, Builder wiring, and Mission Control wiring.

You want to stop Spark

Run spark autostart remove.

Use spark uninstall when you want to remove the local install.

Receipts

The safety proof is still here when you want it.

You do not need to understand every detail to use Spark. But the details are public so humans and agents can check the installer before trusting it.

What is verified

  • The installer scripts have published hashes.
  • The Spark CLI source is pinned to one commit.
  • Managed downloads are versioned and checked.
  • CI does dry-run and real-install smoke tests on macOS, Linux, and Windows.
