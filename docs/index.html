Safe Path

The default flow downloads first, shows a no-write plan, then asks before installing.

The homepage keeps installation to one copyable command. For stricter verification, use the staged path below. It works well for humans and for local coding agents that should inspect privileged scripts before running them.

macOS, Linux, WSL

curl -fsSL https://agent.sparkswarm.ai/install.sh -o spark-install.sh
expected='0ebada64dfebd127f40ab7b4d8d04dc22a546f2b12562de50516be3f87d32e77'
actual=$(if command -v sha256sum >/dev/null 2>&1; then sha256sum spark-install.sh | awk '{print $1}'; else shasum -a 256 spark-install.sh | awk '{print $1}'; fi)
test "$actual" = "$expected" || { echo 'checksum mismatch'; exit 1; }
bash spark-install.sh --dry-run
bash spark-install.sh

Windows PowerShell

iwr https://agent.sparkswarm.ai/install.ps1 -OutFile spark-install.ps1
$expected = 'fb4619737e96b5a84e93f9252c8c05e930e731064d17d85b9ad126a5c238a8e6'
if ((Get-FileHash .\spark-install.ps1 -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expected) { throw 'checksum mismatch' }
powershell -NoProfile -ExecutionPolicy Bypass -File .\spark-install.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\spark-install.ps1

Install Plan

What Spark may create, download, or start.

Local paths

  • ~/.spark/tools for managed runtime tools
  • ~/.spark/bin/spark or %USERPROFILE%\.spark\bin\spark.cmd
  • ~/.spark/env for local setup values
  • ~/.spark/logs/install.log with known secret values redacted

Network allowlist

  • agent.sparkswarm.ai for installer files and metadata
  • github.com/vibeforge1111/spark-cli for Spark CLI source
  • github.com/astral-sh/uv for pinned uv binaries if Python is missing
  • nodejs.org for managed Node when needed

Pinned inputs

  • Spark CLI commit f1fa48f8dd9c59127500bb58e422f5cd2be7a8c0
  • Node 22.18.0
  • Python 3.11 through uv when local Python is not compatible
  • uv 0.11.7 with platform-specific SHA-256 checks

Autostart

Autostart is enabled by default so Telegram replies continue after reboot. Use --no-autostart or -NoAutostart for an inspection-only first install.

Secrets

Telegram bot tokens and LLM keys are configured locally.

The website does not need your Telegram token or provider API key. The installer can pass them into local setup when you choose to provide them, and the install log redacts the known secret values from its output.

BotFather token Create the bot in Telegram, paste the token only into local setup, then rotate it if it appears in chat, screenshots, or logs.
LLM provider key Use your provider console to create the key. Spark stores provider settings locally with the runtime, not on this website.
Agent handoff A local agent can guide setup, but it should stop before transmitting secrets anywhere unexpected.
Lifecycle

Trust improves when the way out is obvious.

Health

  • spark guide opens the walkthrough
  • spark status checks the local runtime
  • spark providers status checks LLM roles
  • spark verify --onboarding checks first-run wiring

Repair

  • spark doctor runs broad diagnostics
  • spark fix telegram repairs a quiet bot
  • spark autostart status checks boot behavior
  • spark verify --deep checks Builder and memory wiring

Remove

  • spark autostart remove stops startup launch
  • spark uninstall removes the Spark install when available
  • Manual fallback: remove ~/.spark after backing up anything you want to keep

Telegram smoke test

  • /start
  • /myid
  • /diagnose
  • Send a normal message and confirm a provider-backed reply

Limits

What is still not a complete supply-chain story.

The installer now has checksums, a release manifest, pinned managed runtimes, immutable Spark CLI source, GitHub Artifact Attestations, Sigstore keyless release signatures, multi-OS dry-run CI, and disposable real-install CI.

Done in this site

  • No remote-script piping required
  • No-write dry-run plan
  • Published hashes and release manifest
  • Ubuntu, macOS, and Windows dry-run plus real-install smoke tests
  • Cosign keyless signatures in GitHub Releases

Next hardening

  • Signed release archives
  • Protected production deploy approvals
