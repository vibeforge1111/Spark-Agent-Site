Start here if you want the smooth path.

The easiest install is not copying a terminal command alone. Ask an AI coding assistant like Codex, Claude Code, or another assistant that can read docs and run terminal commands to open agent.sparkswarm.ai and install Spark with you.

You can still install Spark yourself from the install page. If you are non-technical, start with the assistant-guided path first. It can choose the right Mac, Linux, WSL, or Windows command, run the safety preview, and explain each setup choice.

Spark gives you a Telegram chat door, memory, Spark Live, Researcher, Builder runtime, and Mission Control. You can talk to it, save what matters, research ideas, start builds, and watch work move through Kanban and Canvas.

The self-improving part comes from domain chips: reusable skills Spark can build, test, and reuse. With the right chip, Spark can practice a workflow even while you are away and come back with visible progress instead of vague promises.

Setup

Telegram and your LLM provider are the two keys.

Telegram is how you talk to Spark. The LLM provider is the model Spark uses to think and reply.

Create a Telegram bot Open Telegram, message @BotFather, and create a new bot. Keep the token private.
Find your Telegram ID After Spark starts, send /myid. Use that number as the admin ID.
Choose an LLM provider Start with one provider for the whole agent. You can split agent and mission models later.
Run the checks Use spark live start, spark providers test --role chat, and spark verify --onboarding.
Daily Use

The commands people actually need.

In Telegram

  • /start opens Spark.
  • /diagnose checks what is working.
  • /remember <note> saves a memory.
  • /recall <topic> searches memory.
  • /run <goal> starts a mission.
  • /board shows mission status.
  • /access 3 sets the recommended access level.

In Terminal

  • spark guide opens the walkthrough.
  • spark live start starts the background services.
  • spark live status checks those services.
  • spark providers status checks models.
  • spark providers test --role chat proves the chat model.
  • spark verify --onboarding checks setup.
  • spark security audit checks local launch safety.

Self-Improvement

How Spark turns a task into a specialist.

A domain chip is both a tool Spark can use and a bounded specialization loop Spark Researcher can run.

It gives Spark a way to inspect one kind of work, score it, save the useful lesson, and suggest the next safe experiment.

Domain Chips

The reusable specialist

A chip can focus on startups, trading, research, content, coding, diagnostics, or another repeatable task.

It owns evaluate, suggest, packets, and watchtower behavior for that domain.

Spark Researcher

The local lab

Researcher runs commands, bounded autoloops, memory sync, Obsidian notes, summaries, and reviewable ledgers.

Recursive Loops

The careful repeat

Recursive does not mean uncontrolled.

It means Spark repeats a bounded cycle: run, score, record, suggest, review.

Fixes

When Spark is quiet, check these first.

Most quiet-bot problems come from one of three places: Telegram token, admin ID, or LLM provider setup.

Telegram gets commands, but replies are weird

Run spark providers status.

If the model role is missing, Spark may only show memory labels or empty status text.

Telegram gets nothing

Run spark fix telegram.

Then run spark logs spark-telegram-bot and look for token or polling errors.

Memory does not come back

Run spark verify --deep.

This checks memory, Builder wiring, and Mission Control wiring.

Mission Control is unreachable

Run spark fix spawner.

Then run spark live status and spark logs spawner-ui.

You want to stop Spark

Run spark autostart uninstall.

Use spark uninstall when you want to remove the local install.

Receipts

The safety proof is still here when you want it.

You do not need to understand every detail to use Spark. But the details are public so humans and agents can check the installer before trusting it.

What is verified

  • The installer scripts have published hashes.
  • The Spark CLI source is pinned to one commit.
  • Managed downloads are versioned and checked.
  • CI does dry-run and real-install smoke tests on macOS, Linux, and Windows.

Where to look

  • checksums.txt
  • release manifest
  • GitHub attestations
  • Sigstore signatures
  • security policy
