Spark Agent Docs

The knowledgebase is part of the agent runtime.

Spark Agent docs are backed by the Lore by Spark model from spark-knowledgebase: Markdown source of truth, agent-readable discovery files, provenance-aware retrieval, MCP read/write tools, and trace-derived drafts when agents fail to find the answer.

source: spark-knowledgebase surface: /docs status: static adapter updated: 2026-04-26
Knowledgebase Shape

Lore is the docs engine Spark Agent should mount.

The product brief defines Lore as an agent-native knowledgebase where humans write, agents read, agents propose, and every factual claim carries provenance. For Spark Agent, that means docs are not just marketing copy. They are a runtime surface agents can use before installing, while configuring, and during repair.

Human view

Readable setup, architecture, troubleshooting, module roles, and operating checks.

Agent view

llms.txt, AGENTS.md, Markdown responses, and structured context for Codex, Claude, Cursor, and Spark agents.

Write path

Agents propose edits or new pages as reviewed change requests, with claim-to-source mappings.

Learning path

Search misses, failed citations, broken runbooks, and rejected edits become trace-derived draft pages.

Agent Contract

Every connected agent should know where to start and how to behave.

The Spark Agent knowledgebase should expose a compact self-onboarding contract before any tool call or install command runs.

Read discovery first Agents start from /docs/AGENTS.md and /docs/llms.txt before touching installers or local services.
Use docs as source, not memory theater Answers cite pages, checksums, command outputs, or repo paths. If evidence is missing, the agent says so.
Propose, do not silently mutate Knowledgebase writes land as diffs with provenance. Agent-authored content starts low-authority until reviewed.
Submit traces when docs fail Search misses and broken runbook steps should become structured traces, then draft pages with do_not_infer: true.
Trust Model

The knowledgebase only becomes powerful if it stays falsifiable.

Lore's useful idea is not "AI writes docs." It is "agents reveal what the docs are missing, then the system turns that evidence into reviewable pages."

Authority levels

  • L1 trace-derived drafts are hidden from default retrieval.
  • Promotion requires a human or trusted agent with verified sources.
  • Deprecated or stale chunks stay out unless explicitly requested.

Required receipts

  • Claim text
  • Source URL or local file path
  • Verification timestamp
  • Rollback or revisit condition for high-impact guidance
Installer Boundary

The installer path is safer now, but it is still privileged local execution.

The site now serves /install without the broken HTTP downgrade, and the direct installer files have published SHA-256 checksums plus GitHub Artifact Attestations. That prevents accidental redirect downgrade and gives operators something concrete to verify after download. 

curl -fsSL https://agent.sparkswarm.ai/install.sh -o ./install.sh
expected='07f616ad8ac15686082c244a105add80c41ac61971f3c69e68a48fe965af1ceb'
actual=$(if command -v sha256sum >/dev/null 2>&1; then sha256sum ./install.sh | awk '{print $1}'; elif command -v shasum >/dev/null 2>&1; then shasum -a 256 ./install.sh | awk '{print $1}'; else echo 'Missing sha256sum or shasum'; exit 1; fi)
test "$actual" = "$expected" || { echo 'spark installer checksum mismatch'; exit 1; }
gh attestation verify ./install.sh --repo vibeforge1111/Spark-Agent-Site --signer-workflow vibeforge1111/Spark-Agent-Site/.github/workflows/install-hardening.yml --source-ref refs/heads/main
less ./install.sh
read -r -p 'Run Spark installer now? Type yes: ' answer && case "$answer" in yes) bash ./install.sh ;; *) echo 'Skipped.' ;; esac
iwr https://agent.sparkswarm.ai/install.ps1 -OutFile .\install.ps1
if ((Get-FileHash .\install.ps1 -Algorithm SHA256).Hash.ToLowerInvariant() -ne 'c62c2742d2dcd49030936fdbc8425dd628f6ea84c9402b132ca0c74ede4fafb4') { throw 'install.ps1 checksum mismatch' }
gh attestation verify .\install.ps1 --repo vibeforge1111/Spark-Agent-Site --signer-workflow vibeforge1111/Spark-Agent-Site/.github/workflows/install-hardening.yml --source-ref refs/heads/main
Get-Content .\install.ps1
if ((Read-Host 'Run Spark installer now? Type yes') -eq 'yes') { powershell -ExecutionPolicy Bypass -File .\install.ps1 } else { Write-Host 'Skipped.' }

The installer uses the canonical Spark CLI repository by default and blocks source, ref, and local registry overrides unless the explicit developer flag is set. Stronger assurance still needs signed releases, protected deploys, repo ownership under a verified organization, and ideally Sigstore/minisign signatures. Checksums hosted on the same domain are useful for accidental tamper detection, but they are not a complete defense if the whole deploy surface is compromised.
