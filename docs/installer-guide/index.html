Guided Installer

Install Spark in five calm steps.

This page is for people who want Spark installed without decoding a wall of terminal commands. Let Codex, Claude Code, or another AI coding assistant follow it with you.

Step 1

Tell Codex, Claude Code, or your setup assistant to install Spark.

The easiest path is to ask an AI coding assistant like Codex or Claude Code to read this guide or agent.sparkswarm.ai and install Spark with you. They can usually get you through setup in a few minutes and explain what is happening as they go.

  • The assistant picks the right Mac, Linux, WSL, or Windows install path.
  • It can run the dry run first, so you can check whether the download and installer look secure before installing.

You can still install from terminal by hand, but non-technical users usually have a much smoother time with a coding assistant guiding the install.

Step 2

Choose the LLM Spark will use.

Start simple: choose one default LLM provider for Spark. That can power Agent chat, memory, runtime reasoning, and Mission work while you are getting started.

  • Agent means normal chat, reasoning, preferences, memory, and recall.
  • Mission means Mission Control builds, research, coding, and longer tracked work.
  • You can use one provider for both, or split Agent and Mission during setup.
  • For Anthropic, Spark defaults Agent to Claude Sonnet 4.6 and Mission to Claude Opus 4.7.
  • If you already have a Codex or Claude Code subscription, tell it to connect that with Spark.
  • Use an API key if you prefer Z.AI GLM, Kimi, MiniMax, Gemma, OpenRouter, or DeepSeek-compatible routes.
  • Use local models through Ollama, LM Studio, Hugging Face, or Gemma when your computer is strong enough.
Step 3

Create your Spark Telegram bot.

Open Telegram, search for @BotFather, send /newbot, and follow the prompts. BotFather gives you a bot token. If you already have a bot, you can use that token instead.

  • Spark uses that bot as the chat door to your agent.
  • Your own Telegram account becomes the admin account, so only you can run powerful Spark commands.
  • After setup, this bot becomes Spark: it uses the Agent provider, memory, and Mission tools you connected.
Step 4

Start chatting and build resonance.

Before building, just talk to Spark. Tell it how you like to work, what you care about, what you dislike, and what you want help remembering.

  • Use normal chat for daily ideas, plans, and questions.
  • Use /remember for preferences Spark should keep.
  • Use /recall to check what Spark remembers.
  • Use /diagnose if the bot feels quiet or confused.
Step 5

Build with Spark Mission Control.

When you are ready, ask Spark to build something small. Mission Control shows the work through Kanban and Canvas so you can see what is happening.

  • Start with a tiny app, workflow, or tool.
  • Then build domain chips when Spark needs to master a specific topic or skill.
  • Use autoloops when you want Spark to keep improving a repeated process over time.
  • The Domain Chip Creator path helps turn useful know-how into reusable Spark skills.

Always-on hosting comes after the local path.

For Railway or Docker, Spark should run as two services: Spark Telegram Bot for Telegram chat and private relay, plus Spawner UI for Mission Control. Keep them in the same private network and share one bridge key between them.

Telegram Bot

Runs long polling, Agent chat, and the relay callback.

TELEGRAM_RELAY_HOST=::

Mission Control

Runs Spawner UI, boards, workspaces, and mission state.

SPAWNER_STATE_DIR=/data/spawner

Bridge Key

Lets the two services talk privately without exposing control APIs.

SPARK_BRIDGE_API_KEY
SPAWNER_UI_URL=http://spawner-ui.railway.internal:<port>
SPAWNER_UI_PUBLIC_URL=https://<protected-spawner-public-domain>

Keep internal calls on Railway private DNS, but give Telegram a protected public Spawner URL for mission board links. Each user should normally run this in their own hosting account so costs, workspaces, and secrets stay under their control.

For a cloud smoke test, run the bot with TELEGRAM_SMOKE_MODE=1 and start a tiny Mission from Spawner. When you switch to real Telegram chat, replace the smoke token with the BotFather token and keep persistent volumes mounted at /data.

Use the Railway/VPS operations page when you need the full hosted service map, environment checklist, and production smoke prompt.

A Spark that keeps getting better.

Spark is meant to become a personal system that learns your taste, your projects, and the tools you care about. With the right domain chips and benchmarks, it can keep practicing a skill or workflow even while you sleep. You get to see that progress through memory, visible missions, and recursive self-improvement loops.

Mission board

Users can watch work through Kanban and Canvas instead of guessing what an agent is doing.

Memory

Spark can save useful preferences and facts, then use them in later conversations and missions.

Recursive self-improvement

Spark can create domain chips and tools to master repeatable work, then reuse them on the next loop.
