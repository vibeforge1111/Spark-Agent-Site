# Spark Feedback

Feedback should go to the repo that owns the confusing behavior.

Start with `Spark-Agent-Site` when unsure.

Use `/docs/feedback.md` for the full agent-readable routing map.

Never include Telegram tokens, LLM keys, private memory, private repo content, or unredacted logs in GitHub issues or PRs.

Good feedback names:

- the repo
- the page, command, or module
- expected behavior
- actual behavior
- safe evidence
- smallest suggested improvement
